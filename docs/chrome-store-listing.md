## English short description

Choose your website fonts, add custom fonts, and improve right-to-left text with settings for each site.

## English description

Read the web in the fonts you prefer. FontAra lets you change website fonts and improve right-to-left text, with controls for individual sites or the whole web. It is especially useful for Persian, Arabic, Kurdish, Dari, and pages that mix right-to-left and left-to-right text.

CHOOSE YOUR FONTS

- Pick from bundled open-source fonts.
- Add your own WOFF, WOFF2, TTF, or OTF fonts, with Regular and optional Bold styles.
- Enable installed system fonts or Google Fonts when you want more choices.
- Set a different font and text stroke for individual sites.

CONTROL WHERE IT WORKS

- Turn FontAra on or off for the current site from the toolbar popup.
- Use global mode, inclusion and exclusion lists, or per-site profiles.
- Use smart RTL to improve text direction and alignment in supported pages and editable fields.
- Manage settings in English, Persian, or Arabic, and export or import a backup.

FontAra is designed to preserve icons and code while changing readable text. Some websites may need individual adjustments. Chrome's internal pages, the Chrome Web Store, and other browser-restricted pages cannot be modified.

PRIVACY
Page text is processed in your browser. FontAra has no analytics or advertising. Custom-font files stay in local extension storage and are included in a backup only when you export one. Settings, including saved site rules, can sync through your browser; you can turn this off in settings. Custom-font files and system-font choices do not sync.

Google Fonts is off by default. If you enable it, FontAra downloads and caches the fonts you select from Google without sending the visited page address or content. Google still receives your IP address, normal request metadata, and the requested font resource.

## Privacy practices: single purpose

FontAra lets users personalize the typography of websites they choose by applying their preferred fonts and adjusting right-to-left text direction. Font selection, per-site controls, and RTL handling all serve this single purpose.

## Privacy practices: permission justifications

### Host access (`*://*/*`)

FontAra applies the user's chosen font and text-direction settings to normal HTTP and HTTPS pages, including frames, through its bundled content script. Broad host access is needed because users can enable any website or choose global mode. Site rules determine where changes are applied. Page URLs and text are processed locally for matching and rendering; they are not sent to a FontAra server.

### `storage`

Stores font preferences, site inclusion and exclusion rules, per-site profiles, interface language, and other extension settings. When settings sync is enabled, eligible settings use Chrome's storage.sync service. Custom-font files, cached font binaries, and system-font selections remain local.

### `unlimitedStorage`

Allows the local font library and font cache to exceed the normal storage.local quota. FontAra enforces its own storage limits, including a 50 MiB custom-font library limit. This permission stores font files on the user's device; it does not upload them.

### `fontSettings`

Lists installed font names with chrome.fontSettings.getFontList so users can choose a local system font after enabling that feature. FontAra does not change Chrome's global default-font settings. The font list is not sent to a server.

### `contextMenus` (optional)

Adds quick actions to toggle FontAra globally or for the current site and to open its settings. The permission is requested only when the user enables the context-menu option, and removed when that option is disabled.

## Privacy practices: remote code

Select **No, I am not using remote code** for the 5.1.0 package. All executable
JavaScript is bundled in the extension. Optional Google Fonts requests retrieve
font CSS as data, validate and parse its font declarations, and download WOFF2
font binaries; they do not download or execute JavaScript or WebAssembly.

## Privacy practices: data handling evidence

Use these facts with the current dashboard's field definitions. Local processing
still needs to be disclosed; absence of a FontAra server does not mean the
extension never handles user data.

| Data | Handling in 5.1.0 |
| --- | --- |
| Page addresses and visible/editable text | Used locally to match site rules and determine font/direction. No page content is sent to FontAra or Google Fonts. |
| Saved site rules and preferences | Saved in extension storage; eligible settings sync through the browser unless the user disables sync. Sync is enabled by default, subject to the browser's own sync configuration. |
| Custom-font files and system-font selections | Kept locally and excluded from settings sync. A user-created backup can contain custom-font files. |
| Google Fonts requests | Disabled by default. After opt-in, Google receives the IP address, normal request metadata, and selected font resource. Requests omit credentials and referrers. |
| Analytics, advertising, data sales | None in the extension. |

The privacy-policy URL above explains these uses. Keep the dashboard disclosures,
that policy, and the submitted package consistent. In particular, do not claim
that all data stays on-device, that no network requests are made, or that Google
receives no information.

## Reviewer notes for 5.1.0

No account or payment is required. Open a normal HTTPS page, enable FontAra for that site in the toolbar popup, and choose a bundled font. Settings includes per-site profiles, smart RTL, custom Regular/Bold fonts, backup/import, and English/Persian/Arabic. System fonts, Google Fonts, and context menus are off by default. Google Fonts needs Internet access. Chrome-internal pages and the Chrome Web Store cannot be modified.

## If the published package remains 5.0.0

The local repository has no `v5.0.0` tag. Commit `29a3ece` prepares 5.0.0, but is
not proof that it is identical to the package currently installed from the
Store. Its manifest still requests `tabs` and `<all_urls>`, and its font loading
predates the privacy fixes in 5.1.0. Verify the published package before making
implementation-specific privacy claims about it.
